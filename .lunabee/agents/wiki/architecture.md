# Architecture

One binary `berth`, two roles: short-lived **client** commands + long-lived **daemon**.

```
agent shell → berth claim/run/release/status/top (client, BerthCore.DaemonClient)
berth-bar (menu bar, BerthCore.DaemonWatch + windowed claim/release, never autospawn; scrcpy mirror children)
                 │ NDJSON over Unix socket  <BERTH_HOME>/berth.sock
                 ▼
            berth daemon run (BerthDaemon.Daemon)
              ├─ Server: SwiftNIO UDS, one task per connection
              ├─ Broker actor: slots, leases, FIFO waiters → [[broker]]
              ├─ DeviceBackend → DeviceRouter → AndroidBackend (emulator/adb) → [[android-backend]]
              │                              └ IOSSimulatorBackend (simctl) → [[ios-backend]]
              └─ reap loop every 5 s
```

## Key decisions
- **Daemon auto-spawn**: no socket → client `posix_spawn`s `berth daemon run` w/ SETSID (outlives client, immune to terminal SIGHUP/SIGINT), retries connect 5 s. `flock` on `daemon.lock` → single daemon; loser exits 0.
- **Connection = claim lifetime**: claim open while queued; disconnect → waiter dropped. Grant needs `ack` before disconnect, else lease back to pool. → no leak if client killed mid-wait (Claude Bash 2 min timeout).
- **Persistence**: `state.json` rewritten each change; restart adopts slots w/ serial still in `adb devices` (free/leased kept, transitional stopped).
- **Daemon survives bad accepts (BERTH-18)**: 2026-11-18 incident: `NIOFcntlFailedError` (Darwin, peer closed before non-blocking set) ended NIO's async accept sequence → `Server.run` threw → daemon exit; restarted daemon adopted nothing, 4 emulators orphaned. Now `AcceptErrorFilter` (server-channel handler via `serverChannelInitializer`, in `Server.bind`) swallows only `NIOFcntlFailedError`, logs `accept failed:` max 1/s + held-back count. IOErrors (EMFILE…) left to NIO's `AcceptBackoffHandler` (added after initializer; filter must not starve it). Safety net: `Server.run` loops, sequence end → `cancelAll` live connections, log `server stopped: …, listening again`, rebind after 1 s, same broker. → [[broker]]
- **Paths**: `BERTH_HOME` relocates config/state/socket/logs (default `~/Library/Application Support/berth`, logs `~/Library/Logs/berth`). Socket path ≤ 104 bytes.
- **Shell output → temp files, not pipes**: adb may fork server inheriting pipe → read never EOF.
- **Login items = launchd agents, not `SMAppService`**: `berth-bar` bare executable, no `.app` bundle. Daemon `com.berth.daemon` (`berth daemon install`, KeepAlive, bootstrap now). Bar `com.berth.bar` (panel checkbox + right-click menu item, RunAtLoad only, no KeepAlive → Quit sticks; checkbox never bootstraps/bootouts → no 2nd instance, no self-kill). `berth bar install` writes same plist + bootstraps now (replaces same-path berth-bar), `uninstall` bootouts + removes. Checkbox on ⇔ plist exists. Plist keeps binary path + `BERTH_HOME` from when enabled. berth-bar SIGTERM (bootout, replace) → `NSApp.terminate` → Quit cleanup. → #8, BERTH-14
- **Windowed = human's emulator**: panel "Launch emulator" → claim `windowed: true` (Android pool AVD, label `you`, owner berth-bar) → windowed boot (or reuse free windowed), manual lease forever; release → free pool slot, no reset, any claim takes it as is. One claim loop `DaemonClient.claim` shared by CLI `ClaimFlow` + bar. → [[broker]], #19
- **Mirror = scrcpy child of berth-bar, daemon untouched**: Mirror button on headless Android rows `free`/`leased` → scrcpy (`PATH`, then `/opt/homebrew/bin`, `/usr/local/bin`: launchd PATH minimal), env `ADB` = SDK adb (same adb server as berth), `--no-audio`, title `<serial> <model>`. Free → control; leased → `--no-control` + ` (view only)`. Mirrored free slot gets leased → stop + reopen view-only (scrcpy can't drop control live). One process per serial (2nd click → `activate`). Exit 0/2 (closed, device gone on reset) silent; other exit → caption `mirror <serial> failed, see <logs>/mirror-<serial>.log`. Quit → `applicationWillTerminate` stops own children only. Foundation `Process`, not `Spawn.detached`: bar owns it, sees exit. → #22
- **Physical devices = seen, never leased (BERTH-13)**: daemon reap runs `adb devices -l` once per tick (`DeviceListing.parse`: `emulator-*` → live serials, rest → `PhysicalDevice{serial, model?, state: AdbState}`), snapshot `devices` (decodeIfPresent, `[]` from old daemon), `changed()` only when list differs. Android devices listed whatever the pool (iOS-only / empty pool too); `live` stays pool-gated. Never slots, grants, `maxRunning`. Panel "Devices" section between Emulators and Queue (`DeviceRow`, columns from shared `PanelColumns`), "none connected" when empty; mirror button only on state `device` → scrcpy control mode, title `<serial> <model or serial>`, never downgraded to view-only. `berth status` table unchanged (`--json` carries `devices`). → [[broker]]
- **Wi-Fi devices from the bar (BERTH-22)**: berth-bar runs SDK adb itself (`Wifi/`: `WifiAdb` protocol, `SdkWifiAdb` 15 s per call, `WifiAdbError` = adb's own line), no daemon request, no wire change; daemon lists new device on next poll. Wi-Fi device = serial `ip:port` or `…._adb-tls-connect._tcp` (`PhysicalDevice.isWifi`). Kill column per row (`WifiEligibility`): Kill (emulator), `wifi.slash` Disconnect (Wi-Fi, any state; `no such device` = already gone, row lags adb by a poll; paired phone reconnects by mDNS in ~8–15 s, accepted), `wifi` Switch to Wi-Fi (USB `device`: `ip addr show wlan0` → `tcpip 5555` → `connect <ip>:5555` retried 10 × 1 s; no address → caption). Caption `WifiDeviceActions.caption`. "Pair device…" → `Wifi/Pair/Window/` one `NSWindow` (not popover: `.transient` would close mid-flow; 2nd click → front; close → `PairFlow.cancel()`). `PairFlow` (@Observable): QR `WIFI:T:ADB;S:berth-<random>;P:<password>;;` (CoreImage, no dep), polls `adb mdns services` 1 s until 120 s deadline (`PairClock`), `adb pair`; or pairing code (`ip:port` + code, fields kept on error); failed QR pair → code screen prefilled. Connect after pair: 10 s for adb auto-connect → `_adb-tls-connect._tcp` service named by adb's `[guid=…]` → manual "IP address & Port". Phone matched by `<guid>.` or `<ip>:` serial prefix. No CLI command: pairing needs a human. Real-phone proof opt-in: `BERTH_WIFI_PHONE=<usb serial>` / `BERTH_WIFI_MDNS_SERIAL=<serial>` `swift test --filter RealPhoneWifiTests`.
- **Device clipboard → Mac (BERTH-23)**: `doc.on.clipboard` button, column after Mirror (panel 650 → 680 pt), on Android slots `free`/`leased` (windowed too) + device rows state `device` (`ClipboardEligibility`); no iOS. Android has no clipboard shell command (`cmd clipboard` → `No shell command implementation.`, `dumpsys clipboard` empty, `service call clipboard` per-version/vendor → rejected) → berth-bar drives installed **scrcpy server** itself, SDK adb only, no daemon request: `ScrcpyServerLocator` (`SCRCPY_SERVER_PATH`, else `<scrcpy dir>/../share/scrcpy/scrcpy-server`) + `ScrcpyVersion` (`scrcpy --version`, server refuses other version) in BerthCore; push `/data/local/tmp/berth-scrcpy-server.jar` (not scrcpy's path → running mirror untouched), `forward tcp:0 localabstract:scrcpy_<scid>`, `app_process … video=false audio=false control=true tunnel_forward=true send_device_meta=false power_on=false cleanup=false clipboard_autosync=false`, dummy byte → `GET_CLIPBOARD` `[8,0]` → `CLIPBOARD` (type 0, u32 BE len, UTF-8). No reply when clip has no text → 3 s silence = empty. adb accepts before server listens then drops → retry closed connection. Budget 12 s read + 3 s shared cleanup (socket close, server stop, device `pkill -f 'com.genymobile.[s]crcpy.Server .*scid=<scid>'` when start hung, `forward --remove -s <serial>` or found by `forward --list`). `ClipboardActions` caption: `Reading clipboard of <serial>…` → `Copied clipboard of <serial>` / `<serial>: clipboard empty` (Mac pasteboard untouched) / error line; one read per serial in flight. `MacPasteboard` protocol (`NSPasteboard.general`) → tests never touch real clipboard. Text only, device → Mac only. Real-device proof opt-in: `BERTH_CLIPBOARD_SERIAL=<serial>` (`BERTH_CLIPBOARD_EXPECTED`) `swift test --filter RealDeviceClipboardTests`.
- **Unmanaged emulators = devices too (BERTH-17)**: `DeviceListing.emulators` = every `emulator-*` entry, whatever the pool (`live` stays pool-gated). Broker publishes emulators that are no slot (any state, `preparing`/`stopping` included) in snapshot `devices`, after phones, sorted by serial. Name = AVD name (`DeviceBackend.avdName`, `adb emu avd name`) stored in `PhysicalDevice.model`, cached per serial in `avdNames` (failure cached too) until serial leaves the list; fallback `model:` field. Same panel row + mirror as phones, no wire change. Never adopted, granted, counted, stopped by daemon: may be a crashed daemon's orphan still used by an agent (BERTH-18 incident). Kill button (⊗) on those rows only (`KillEligibility`: `emulator-*` device row, any adb state): berth-bar runs `adb -s <serial> emu kill` itself (`Launch/Kill/`: `EmulatorKiller` protocol, `AdbEmulatorKiller` 15 s, `EmulatorKillError`), no daemon request; no confirm, tooltip warns; failure → launcher caption; row leaves on next reap. → [[broker]]
- **iOS mirror = DeviceHub, not a child**: Mirror button also on iOS rows `free`/`leased` → `NSWorkspace` opens `devices://device/open?id=<udid>` (Xcode 27 DeviceHub, `com.apple.dt.Devices`; undocumented URL, proven by hand: compact window, attaches to `simctl`-booted sim w/o reboot). No view-only mode → input reaches leased sim; tooltip warns. Bar keeps no session: no free → leased switch, no stop on Quit. No `devices` handler → caption `DeviceHub not found: needs Xcode 27`. No Simulator.app fallback (Xcode ≤ 26). → [[ios-backend]], #29
- **Agent mirror = `berth mirror`, CLI-only**: agent needing human action (login, 2FA, captcha) opens same window from its shell. CLI reads snapshot (`autoSpawn: false`), slot must be `leased` (no owner check, like release/renew), then Android → `Spawn.detached` scrcpy with control + `ADB` env, iOS → DeviceHub URL. Returns at once (shell timeout ~2 min, DeviceHub gives no exit): agent asks user in chat. No pid kept: release restarts emulator → scrcpy exits itself. Bar unaware → 2nd window possible (accepted). No daemon / protocol change. → [[cli]], [[claude-code]], #30
- **Prepare + AVD menus from the bar (BERTH-16)**: prepare = daemon request (broker holds AVD, `preparing` slot, live pool join on success → [[broker]]); `berth prepare` = thin client of same request. Bar reads AVDs on disk itself (`AVDCatalog`) on each popover open — no protocol field, no `emulator -list-avds` in reap. "Launch emulator" = every Android AVD on disk: pool AVD → windowed claim (#19), non-pool → plain `Spawn.detached` `emulator -avd <name>` (window, quickboot, log `emulator-<avd>.log`, outlives Quit, untracked); unprepared suffixed `(not prepared)`. "Prepare AVD" = AVDs not (in pool and prepared) → `DaemonClient.prepare(autoSpawn: false)`, progress = `preparing` row, failure → error caption. Prepare is the only way into the pool.
- Emulators spawned w/ `POSIX_SPAWN_CLOEXEC_DEFAULT` → no inherited daemon socket fds.

## Extending
- Platforms: one pool, queue, `maxRunning` for Android + iOS (eviction across platforms OK, same RAM). Broker knows platform only to filter claims. → [[ios-backend]]
- GUI: done → `BerthBar`.
